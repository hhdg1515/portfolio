Give a Maybach owner a reason to trust an independent workshop over the dealer.

The credibility problem could not be solved with luxury language alone. I designed the site around proof: real repair depth, marque-specific knowledge, bilingual access and a technical archive that search engines and customers could both understand.

I owned the work from information architecture and visual direction through React implementation, content systems, testing, deployment and production maintenance.

Project vision
A workshop site that earns trust through technical specificity rather than dealer-like claims.
Primary users
Owners of European luxury and performance vehicles, including bilingual customers looking for specialist diagnosis and repair.
My scope
Product definition, sitemap, interface system, responsive behavior, React architecture, bilingual content, booking integration, SEO, testing and deployment.
Constraint
The workshop, equipment and photography were still arriving in stages. The site had to launch as a finished product before the image library was complete.
Product & design decisions

The strongest decisions were about
what the client should not have to maintain.

The first design review was a running build.

Decision

There was no visual brief, so I began with a FigJam sitemap and a working React structure. The visual direction came from the client’s trade: Mercedes black, white, grey and blue, treated as familiar workshop language rather than borrowed prestige.

The client reviewed and approved an operating site, not a static mockup. Later, their request for a dedicated Sprinter page corrected the original passenger-car sitemap and made the business model more accurate.

The backend decision was deliberately deferred.

Decision

The public site was the only confirmed priority. Future locations, staff workflows and a possible parts business were still undefined, so building an internal system would have locked in assumptions too early.

I connected booking to the client’s Squarespace account instead. It solved the immediate need while keeping the path open for a custom multi-location system later.

Desktop browsing and mobile navigation were different jobs.

Decision

On-site staff feedback showed that phone visitors could not tell where they were or reach the next destination quickly. Desktop visitors could browse; phone visitors usually wanted one answer.

The mobile version therefore received explicit navigation and a hamburger menu. It was not added because it was conventional, but because the mobile task was orientation rather than editorial browsing.

The site had to feel complete before its photography was complete.

Decision

Interior photography depended on the workshop fit-out. Vehicle photography depended on a specific car arriving and its owner agreeing to a shoot. Neither could define the launch schedule.

I made the technical archive carry the visual and credibility load instead: 50 repair cases, marque-specific narratives and 49 hand-drawn schematics that remain meaningful even when a case has no ideal photograph.

Production architecture

Static at runtime.
Heavy in authored content.

React was chosen before the first screen because the staged commercial build needed reusable page and content modules. The final production system stays deliberately static: no database, no custom server and no CMS.

Frontend
React 18, Vite, React Router and CSS Modules. Route-level code splitting keeps page code and the Three.js navigator off the critical path until needed.
Content
Static ES modules organize 50 repair cases across 16 technical categories and 17 marques. No database or CMS is required to serve them.
Languages
A small custom language context serves English and Chinese. CI checks key parity and prevents Chinese copy from leaking into English fields.
Booking
Squarespace booking opens through a validated external link, keeping account ownership and recurring cost with the client.
Progressive enhancement
The orbiting brand navigator loads only on a capable desktop viewport without reduced motion. Every failed gate produces a complete keyboard-accessible list instead.
Delivery
Vercel with security headers. CI gates language parity, sitemap coverage, build, unit tests and Playwright checks on desktop and mobile.
SEO guardrail
A case opened under the wrong marque can render for recovery, but it is removed from the index and emits no structured data, preventing duplicate-content combinations.

Engineering investigations

Two bugs that looked small
until the baseline was questioned.

A white line one physical pixel wide.

ProblemA service card flashed a one-device-pixel white line during hover, only at fractional display scaling and only mid-animation.
MethodA Playwright probe sampled the card edge across hundreds of frames and reran controlled CSS variants at two device-pixel ratios.
FixThe gradient moved into the transforming image layer so both shared the same rasterized edge; the details reveal timing and dark fallback were corrected.
ProofZero bright pixels across 800+ sampled frames. The probe remains in the repository as a regression tool.

CI was green and checking the wrong thing.

ProblemTwo real landing pages were absent from the sitemap while the sitemap check passed every build.
CauseThe check compared the committed sitemap with the generator’s own output. A route unknown to the generator was missing from both sides, so both sides still matched.
FixThe coverage baseline moved to the router. Static indexable routes are extracted, explicit exclusions are subtracted and any missing URL fails the build by name.
ProofThe blind spot was manufactured deliberately to confirm the new guard fails. No traffic lift is claimed without route-level before-and-after evidence.
Outcome

One accountable owner
from product decision to production guardrail.

  • The client received a live bilingual site without inheriting a custom backend or CMS they did not need.
  • Commercial constraints shaped the architecture, responsive behavior and content strategy—not just the visual layer.
  • Production maintenance includes the invisible work: language parity, canonical URLs, fallbacks, regression probes and route coverage.
